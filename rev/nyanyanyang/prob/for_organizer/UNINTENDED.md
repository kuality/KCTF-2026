# nyanyanyang 언인텐 검토

검토 대상은 최종 참가자 패키지의 stripped 바이너리
`prob/for_user/nyanyanyang`이다. 아래 항목은 `make verify`가 자동으로 재검사한다.

| 후보 풀이/문제 | 판정 | 근거 |
| --- | --- | --- |
| 공개 파일에 평문 플래그 또는 부분 문자열 존재 | PASS | 플래그 전체, 정답/미끼 패스프레이즈, 플래그 본문의 모든 12바이트 슬라이딩 윈도우를 전 파일에서 검색한다. |
| 성공 분기 패치만으로 플래그 획득 | PASS | 플래그는 패스프레이즈를 키로 봉인되어 있다. 검증을 통과시켜도 키가 틀리면 복호화 결과가 쓰레기 바이트이며 `CHECK`에서 걸린다. `CHECK`까지 패치해도 평문은 존재하지 않는다. |
| 미끼 패스프레이즈가 정답으로 인정 | PASS | `verify_legacy`는 `main()`에서 함수 포인터가 덮어써져 호출되지 않는다. 역산 결과를 입력하면 거절되는 것을 런타임 검증에서 확인한다. |
| 둘 이상의 입력이 정답으로 인정 | PASS | 9개 stage가 각각 전단사이고 합성도 전단사다. 길이가 24로 고정된다. 초기 설계에서 stage 2/6이 상쇄되고 3/4가 교환되어 해가 4개였던 문제는 stage 3에 인덱스 의존성을 추가하고 stage 6의 회전량을 바꿔 해결했다. |
| 순서를 모른 채 훨씬 짧은 우회 가능 | PASS | 목표값만 추출해서는 입력을 알 수 없다. 디버거로 상태를 덤프하는 방식은 동일한 9개 연산과 순서를 알아내는 intended 풀이의 변형으로 분류한다. |
| 무차별 대입으로 난이도 우회 | PASS | 24바이트 입력 공간은 탐색 불가능하다. 반대로 9! = 362880 순서 탐색은 의도된 대체 경로이며 1초 안에 끝난다. 두 경로 모두 stage 의미 파악을 요구한다. |
| 공식 솔버가 소스, 시드, 플래그를 참조 | PASS | 솔버는 배포 바이너리 경로 하나만 인자로 받는다. 상수는 파일에서 직접 찾아내고, 솔버 안에 플래그나 패스프레이즈 문자열이 없다. |
| 디버그/컴파일 산출물 유출 | PASS | `-s`로 심볼을 제거한다. 공개 폴더는 바이너리와 README만 허용한다. |
| 예외/비정상 입력이 fail-open | PASS | EOF, 빈 입력, 길이 불일치, 비 ASCII 입력은 모두 거절된다. 종료 코드도 0이 아니다. |
| 플랫폼 의존 불안정성 | PASS | non-PIE ELF x86-64. 정답 반복 실행과 솔버 재현을 검증에서 확인한다. |

## 결론

검토한 범위에서 순서 복구를 건너뛰는 알려진 언인텐은 없다.
로컬 바이너리이므로 참가자가 패치, 디버깅, 메모리 덤프를 하는 것은 막지 않는다.
다만 그 결과로 얻는 것은 stage 의미와 순서이며, 이는 intended 풀이의 변형이다.
