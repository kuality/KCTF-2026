# murthehelp Design

## Goal

전작 `stepped into the crowd` 의 리벤지. 전작이 빨리 뚫린 원인은 두 가지였다.

1. 소스를 전부 공개했다.
2. 취약점 세 개가 모두 공개 라이트업이 많은 조합이었다 (길이확장,
   프로토타입 오염, EJS 가젯).

이번에는 소스를 배포하지 않고, 마지막 단계를 **공개 자료가 존재하지 않는
자체 제작 평가기**로 바꿨다. 검색으로 해결되는 지점을 없애는 것이 핵심이다.

## 컨셉

드라마 <킬러들의 쇼핑몰>의 머더헬프를 그대로 가져왔다. 농기구 쇼핑몰로 위장한
지하 무기 창고이고, 코드에 따라 등급을 나눈다.

| 코드 | 역할 | 문제에서 |
| --- | --- | --- |
| 옐로코드 | 뒷처리 업자 | 처음 발급되는 등급 |
| 퍼플코드 | 스파이 | 중간 등급 |
| 레드코드 | 킬러 | 중간 등급 |
| 그린코드 | 관리자 | 지하 창고 접근 권한. 목표 |

## 체인

### 1단계 — ECDSA nonce 재사용

    k = HMAC(NONCE_SECRET, floor(unixtime))

초 단위라 같은 초에 발행된 영수증 두 장은 같은 k 를 쓴다.
r 이 겹치면 다음으로 개인키가 복구된다.

    k = (e1 - e2) / (s1 - s2)
    d = (s1 * k - e1) / r

개념은 유명하지만 실제로 뚫으려면 동시 요청을 직접 설계해야 하고,
서명 대상 문자열과 해시, 인코딩을 전부 맞춰야 한다.
`/order` 응답이 `message` 를 그대로 돌려주므로 서명 대상은 추측이 아니라
관찰로 알 수 있다. 블랙박스지만 추측 게임은 아니다.

복구한 키로 `grade=그린코드` 회원증을 직접 서명해서 만든다.

### 2단계 — 자체 제작 표현식 평가기 탈출

`/label` 은 `{{ ... }}` 식을 평가한다. 그린코드만 접근할 수 있다. 문법 단계에서 다음을 막는다.

  - 점 접근, 대괄호 접근
  - 허용 목록 밖 함수 호출
  - 40자를 넘는 문자열 리터럴

구멍은 하나다. 이름 해석이 네임스페이스 구분자 `:` 로 쪼갠 뒤
필터 없이 체인을 따라 내려간다.

    shop                          -> "머더헬프" (문자열)
    shop:constructor              -> String
    shop:constructor:constructor  -> Function

Function 을 얻으면 본문은 평범한 JS 이므로 평가기의 제약이 적용되지 않는다.

40자 제한은 `concat` 으로 나눠 조립하면 우회된다. 이것도 의도된 단계다.
구멍을 찾은 뒤 한 겹 더 생각하게 만든다.

## 왜 이 구멍인가

`.` 과 `[` 를 명시적으로 막고 에러 메시지로 알려주기 때문에, 참가자는
"다른 통로가 있다"는 것을 인지한 상태에서 탐색을 시작한다.
`/label/help` 가 네임스페이스 기능을 문서로 알려주므로 단서도 있다.
공개 라이트업이 없어 패턴 매칭이 통하지 않지만, 추측할 필요도 없다.

## 블랙박스 상태에서 주는 단서

소스를 감추는 대신 응답을 관찰 가능하게 만들었다.

| 단서 | 위치 |
| --- | --- |
| 회원증 형식 스펙 | `BAD_FORMAT` 응답 |
| 서명 대상 문자열 | `/order` 응답의 `message`, `/me` 의 `raw` |
| 영수증과 회원증이 같은 키 | `/me` 의 `note`, `BAD_SIGNATURE` 의 `hint` |
| 필요한 등급 | `GRADE_REQUIRED` 의 `need` / `got` |
| 평가기 규칙과 함수 목록 | `/label/help` |
| 네임스페이스 존재 | `/label/help` 마지막 항목 |
| 차단 사유 | `EVAL_REJECTED` 의 개별 메시지 |

감춘 것은 "이 조각들을 어떻게 조합하면 뚫리는가" 뿐이다.
