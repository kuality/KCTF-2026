# inkspill 출제자 풀이

> 이 문서는 출제자 전용이다. 참가자 배포물에 포함하지 않는다.

## 취약점과 목표

`Submit report` 메뉴는 스택의 제보문을 검증한 뒤 그대로
`printf(report)`에 전달한다. 포맷 검증기는 출력 폭과 변환 개수를 제한하고
`%s` 및 여러 번의 쓰기를 차단하지만, 의도적으로 단 한 번의 `%hn`을 허용한다.
바이너리는 non-PIE이므로 전역 `approval`의 주소는 고정이다.

최종 빌드에서 다음 두 상수를 사용한다.

- `approval`: `0x405000`
- 제보문 시작 슬롯: 8번 인자, 주소 슬롯은 10번 인자 (`%10$...`)
- 승인 값: `0x0539` (10진수 1337)

공식 solver는 첫 연결에서 `AAAABBBB|%1$p|...|%12$p`를 보내 제보문 시작
슬롯을 자동 확인한다. 따라서 최종 공통 툴체인 재빌드 후에도 offset 변화가 있으면
즉시 감지해 두 번째 연결의 위치 지정자를 다시 계산한다.

## 익스플로잇

`%1$1337c`로 지금까지 출력한 문자 수를 1337로 만든 뒤, 제보문 내부의
`approval` 주소를 `%10$hn`으로 선택해 쓰기를 수행한다. 주소 앞에는 NUL을
두므로 주소의 `0x00` 바이트가 포맷 문자열로 해석되지 않는다. 전역 변수의
상위 16비트는 초기값 0인 채 유지되어 전체 값이 정확히 `0x00000539`가 된다.

현재 검증된 payload 레이아웃은 다음과 같다. 제보문 시작은 `printf`의 8번 인자이고,
주소는 제보문 기준 16바이트 오프셋에 정렬된다.

```text
offset 0x00: "%1$1337c%10$hn\0"
offset 0x0f: "A"
offset 0x10: p64(0x405000)
```

쓰기가 끝나면 같은 연결에서 메뉴 2를 정상 호출한다. 이 별도 동작이 승인 값을
확인한 경우에만 saved UID인 `pwn`을 effective UID로 복원하고
`/home/pwn/flag`를 연다. 일반 연결 동안 real/effective UID는 모두 `user`다.

```sh
python3 solve.py 127.0.0.1 20001
```

공식 solver는 `HOST PORT` 두 위치 인자만 받으며, 권한 복구까지 포함한 전체 체인은
Docker TCP 서비스에서 검증한다.
