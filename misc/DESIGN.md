# KCTF 2026 — MISC 카테고리 설계

## 컨셉

"AI로 보안에서 이런 것도 가능하다"를 보여주는 3문제.
AI는 **정답을 알려주는 오라클이 아니라, 사람이 손으로는 못 할 대량 작업을 처리하는 도구**로 쓰인다.

세 문제가 각각 다른 AI 능력을 시연한다:

| # | 문제 | 시연하는 AI 능력 | 난이도 |
|---|------|-----------------|--------|
| 1 | `shredded` | Vision / OCR — 열화된 이미지 수백 장에서 텍스트 대량 추출 | LOW |
| 2 | `inbox-triage` | Semantic triage — 대량 자연어 데이터에서 이상 신호 선별 | LOW–MED |
| 3 | `intel-chain` | Cross-document reasoning — 이종 문서 교차 상관분석 (TI) | MED |

## 전 문제 공통 규칙

1. **반출 방지 (anti-shortcut)**: 번들 전체를 프론티어 모델에 그대로 넣고 "플래그 찾아줘" 했을 때 나오면 안 된다. 어떤 단일 아티팩트도 답을 담지 않고, 조립에는 사람이 설계한 파이프라인이 필요해야 한다. → **출제 전 반드시 이 테스트를 직접 돌린다.**
2. **무료 경로 보장**: 유료 API(GPT-4V/Claude Vision)가 있어야만 풀리면 pay-to-win이다. tesseract + 전처리, 또는 오픈웨이트 VLM으로도 풀리는지 검증한다. AI는 *빠르게* 만들어주는 것이지 *가능하게* 만드는 게 아니다.
3. **오프라인 완결**: VirusTotal 등 외부 조회 불필요. 대회 중 rate limit으로 깨지지 않고, 대회 후에도 영구 보존된다.
4. **실제 IOC 금지**: 전부 합성. IP는 RFC 5737 (`192.0.2.0/24`, `198.51.100.0/24`), 도메인은 `example.com` 계열. 솔버가 실제로 찔러보는 사고를 막는다.
5. **오류 감지 가능성**: 솔버가 자기 결과가 틀렸다는 걸 *알 수 있어야* 한다. 조용히 틀린 플래그가 나오면 안 된다. (문제 1의 base32 + magic bytes가 이 원리)
6. 플래그 포맷: `KCTF{...}`

## 문제 1 — `shredded` (LOW, OCR)

### 스토리
사내 문서 파쇄기 옆에서 회수한 종잇조각 400장을 스캔했다. 복원하라.

### 구성
- PNG 이미지 400장. 각 장에 한 줄: `037: MFRGGZDFMZTWQ2LK`
- 조각을 인덱스 순으로 이어붙이면 **base32 문자열** → 디코드하면 플래그가 그려진 작은 PNG (또는 ZIP)
- 이미지 열화: 회전 ±3°, 가우시안 노이즈, JPEG 아티팩트, 폰트 3종 혼합, 배경 얼룩/접힘 자국

### 왜 base64가 아니라 base32인가 (핵심 설계)
OCR은 `0/O`, `1/l/I`를 반드시 혼동한다. base64 알파벳은 이 문자를 전부 포함해서 오류 복구가 지옥이 된다.
**base32(RFC 4648)는 `A-Z2-7`** — `0`, `1`, `8`, `9`가 아예 없고 대문자 전용이라 `O/0`, `l/I` 혼동이 구조적으로 불가능하다. 난이도를 LOW로 유지하면서 열화는 세게 줄 수 있다.

### 자가검증
디코드 결과의 PNG magic bytes(`89 50 4E 47`)가 검증 역할을 한다. OCR 오류가 있으면 즉시 깨지고, 솔버는 후보 문자 치환으로 좁혀갈 수 있다.

### 난이도 조절 손잡이
- 인덱스 중복(재파쇄본) 몇 장 넣고 "워터마크 있는 쪽이 유효" 같은 규칙 → LOW 유지하려면 이건 **빼거나 아주 약하게**
- 이미지 장수: 400장이면 수작업 불가 + AI로는 몇 분. 적정선.

## 문제 2 — `inbox-triage` (LOW–MED, Semantic triage)

### 스토리
침해사고 대응 중이다. 직원 메일함 덤프 600통을 받았다. 실제로 자격증명이 유출된 그 한 통을 찾아라.

### 구성
- `.eml` 600통 (합성). 정상 업무 메일 + 뻔한 스팸 디코이 수십 통
- 진짜 한 통의 특징:
  - 헤더: SPF fail + display-name 스푸핑 (`"IT Helpdesk" <helpdesk@examp1e-corp.com>`)
  - 본문: 스팸 티가 안 나는 자연스러운 사내 공지 톤 ← **여기가 핵심**
  - 첨부: 난독화된 HTML credential harvester
- 플래그: 첨부 HTML 난독화 해제 → POST 대상 URL 파라미터에 존재

### 왜 grep으로 안 풀리는가
디코이 스팸들이 `password`, `verify`, `urgent` 같은 키워드를 똑같이 가지고 있다. 키워드 매칭은 수십 개 후보를 뱉는다.
구분점은 **문체와 맥락의 자연스러움** — 정확히 LLM이 잘하고 정규식이 못 하는 영역이다. AI로 600통 분류·요약해서 후보를 3~5통으로 좁히는 게 정석 풀이.

## 문제 3 — `intel-chain` (MED, Threat Intelligence)

### 스토리
합성 APT 캠페인 "BLUEHERON"에 대한 인텔 번들을 받았다. 유출 채널을 특정하라.

### 번들
- `BLUEHERON_report.pdf` — 12페이지 합성 APT 리포트. 일부 페이지는 **스캔 이미지**(문제 1의 OCR 능력 재활용)
- `sandbox/*.json` × 3 — Cuckoo 유사 포맷 동적분석 리포트
- `iocs.csv` — 200행, 대부분 노이즈
- `traffic_summary.txt` (또는 소형 pcap)

### 체인 (4단계, MED 상한)
1. 리포트에서 캠페인 3차 웨이브의 샘플 SHA256 식별
2. 그 해시를 가진 샌드박스 리포트 → C2 도메인 추출
3. IOC CSV에서 해당 도메인 행 → `first_seen` 타임스탬프
4. 트래픽 요약에서 그 시각 세션 → 페이로드가 XOR 인코딩, **키는 리포트에 나열된 MITRE ATT&CK 기법 ID 시퀀스**

어떤 단일 문서도 답을 담지 않는다 — 4개 문서를 전부 조인해야 한다. MITRE ATT&CK 기법 ID는 공개 정보라 안전하다.
