# canary-index

| | |
|---|---|
| **카테고리** | MISC |
| **난이도** | LOW–MEDIUM |
| **플래그** | `KCTF{c4n4ry_m4tch_782992d2c39953d39ab94a74}` |
| **배포물** | `dist/canary-index.zip` |
| **시연 능력** | Semantic matching — 바꿔 쓴 HUMINT 유출문과 개인화 브리핑 대량 대조 |

---

## 문제 설명

> Norite Systems는 정보 유출자를 찾기 위해 수신자마다 일부 사실이 다른 브리핑을
> 배포했다. 외부에 올라온 익명 게시물 12개가 어느 사본에서 유출되었는지 찾아라.
>
> 유출자는 문장을 그대로 복사하지 않았다.

첨부: `canary-index.zip`

## 배포 구성

```
canary-index/
├── NOTES.txt
├── BRIEFINGS/                 개인화 브리핑 972개
└── LEAKS/                     바꿔 쓴 유출문 12개
```

각 유출문은 호출명·장소·시각·차량이라는 네 사실을 포함한다. 한 사실만 일치하는
브리핑은 많고, 세 사실이 일치하는 근접 오답도 의도적으로 넣었다. 네 사실의 의미가
전부 일치하는 문서는 유출문마다 하나다.

## 의도된 풀이

1. AI나 로컬 임베딩으로 각 유출문의 네 사실을 정규화한다.
2. 972개 브리핑을 표로 만들고 의미가 같은 후보를 순위화한다.
3. 네 사실 모두가 일치하는 `BRIEFING-ID`를 `LEAK-01`부터 순서대로 얻는다.
4. `NOTES.txt`의 명세대로 ASCII ID를 `|`로 연결하고 SHA-256 앞 24글자를 계산한다.

레퍼런스 솔버는 사람이 한 번 해석한 동의 표현 사전을 코드로 고정한 무료 경로다.
외부 API가 없어도 표준 라이브러리만으로 완주한다.

```
$ python3 solve.py
leak_01.txt: BRF-FD35B8F  (4/4 facts; runner-up 3/4)
...
FLAG: KCTF{c4n4ry_m4tch_782992d2c39953d39ab94a74}
```

## 설계 노트

### AI가 만든 문장을 키로 쓰지 않는다

AI는 의미가 같은 문서를 찾는 데만 관여한다. 최종 플래그 재료는 파일 헤더에 실제로
적힌 ASCII `BRIEFING-ID`다. 유니코드 정규화, 번역 표현, 모델 출력 형식에 영향을
받지 않는다.

### 단일 단서와 단순 문자열 유사도는 답이 아니다

각 유출 후보군을 4개 필드의 완전한 `3^4` 격자로 만들었다. 따라서 정답을
포함한 모든 브리핑이 한 필드만 다른 이웃을 정확히 여덟 개 가지며, 이웃 수로 중심점을
찾는 우회가 없다. 원문과 유출문은 핵심
명사를 그대로 복사하지 않도록 바꿨다. `audit.py`는 다음을 검사한다.

- 모든 유출문에서 4/4 일치는 정확히 하나
- 차점은 반드시 3/4
- 3개 이상만 맞춰 찍는 조합은 최소 `9^12`, 고정된 세 사실만 쓰는 전략도 `3^12 = 531,441`
- 정답 파일 크기가 일관되게 크거나 작지 않음
- 모든 브리핑이 UTF-8 기준 동일한 700바이트이며 Hamming 차수가 정확히 8
- ZIP은 무압축 저장해 압축 크기 차이도 후보 판별자가 되지 않음
- 평문 문자 유사도 순위가 정답 오라클로 작동하지 않음

### 게싱

플래그의 해시는 배포물에 정답 검증값으로 존재하지 않는다. 잘못 고른 ID도 그럴듯한
해시형 플래그를 만들기 때문에 로컬에서 후보를 대입해 확인할 수 없다. 각 유출문의
네 사실이 모두 맞는다는 객관적 근거로만 선택해야 한다.
