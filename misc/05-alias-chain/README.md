## 문제 설명

> 확인된 포럼 계정 하나가 있다. 운영자는 다른 플랫폼에서 사용자명을 전혀 재사용하지
> 않았다. 공개 아카이브만으로 블로그, 리뷰, 여행기, 중고장터, SNS의 별명을 차례로
> 연결하라.

첨부: `alias-chain.zip`

## 배포 구성

```
alias-chain/
├── GUIDE.txt
├── START_PROFILE.txt
├── BLOG/                       HTML 27개
├── REVIEWS.jsonl               리뷰 계정 27개
├── TRAVEL/                     여행기 TXT 27개
├── MARKET.csv                  장터 계정 27개
└── SOCIAL/                     JSON 27개
```

## 의도된 풀이

`GUIDE.txt`가 플랫폼 순서를 고정한다.

```
START -> BLOG -> REVIEWS -> TRAVEL -> MARKET -> SOCIAL
```

현재 계정의 개인적 경험 세 가지를 추출하고, 다음 플랫폼에서 같은 경험을 다른 말로
표현한 유일한 계정을 찾는다. 정답 계정에 남은 세 이야기가 다음 단계의 피벗이 된다.
사용자명은 전혀 재사용하지 않으며 파일명과 배열 순서도 무작위다.

다섯 `PROFILE-ID`를 순서대로 `|`로 연결해 `GUIDE.txt`의 SHA-256 플래그 공식을 적용한다.

```
$ python3 solve.py
BLOG   : PRF-AE9AE491  (3/3 memories; runner-up 2/3)
REVIEWS: PRF-42A23290  (3/3 memories; runner-up 2/3)
TRAVEL : PRF-D72966AB  (3/3 memories; runner-up 2/3)
MARKET : PRF-E2D366E3  (3/3 memories; runner-up 2/3)
SOCIAL : PRF-E97C1A71  (3/3 memories; runner-up 2/3)
FLAG: KCTF{4l14s_ch41n_0dff2f984c5429eeca69c499}
```

## 설계 노트

### OSINT 모양이지만 외부 인터넷은 없다

HTML·JSONL·TXT·CSV·JSON으로 저장한 합성 공개 아카이브만 사용한다. 계정 검색이나
실제 인물 조회가 필요 없고, 대회 후에도 그대로 재현된다.

### 세 단서의 교집합만 유일하다

각 플랫폼의 세 의미 필드를 완전한 `3×3×3` 격자로 만들었다. 3/3 일치는 하나지만,
2/3 이상 일치 후보는 일곱 개다. 다음 계정으로 넘기는 세 이야기에도 같은 격자를
적용해 모든 계정의 정확 문장 빈도 서명은 `(9,9,9,9,9,9)`로 같다. 한 경험을 검색해
고르거나 두 단서만 보고 찍으면 체인 전체에서 최소 `7^5 = 16,807`개가 남는다.

### 생성기 흔적 제거

정답 계정은 다음 피벗 세 개까지 포함하므로 초안에서는 파일이 더 길었다. 현재는 모든
프로필 본문을 UTF-8 기준 정확히 900바이트로 맞췄고, ID·핸들 길이도 동일하다.
ZIP도 무압축 저장해 압축률이 내용 길이 오라클로 돌아오는 것을 막았다. `audit.py`는
플랫폼별 본문 크기 집합과 문장 빈도 서명이 하나인지 단언한다. 파일명·행 위치는 생성 후 섞고 정답이
첫·마지막 위치에 놓이지 않게 하며, 정답 ID와 사용자명에는 공통 접두사 외 패턴이 없다.
공백을 제거한 실제 본문 길이에서도 정답이 상·하위 네 개에 들지 않도록 감사한다.

블라인드 검증 중에는 특정 인공 접미사가 없는 프로필만 거르면 단계마다 27개가 8개로
줄어드는 흔적도 발견됐다. 최종본은 모든 꼬리 사실에 같은 접미사를 적용했다.
접미사 개수도 27개 전원 같고, 접미사를 전부 제거해도 모든 행의 문장 빈도 서명이
같아 이 필터는 더 이상 후보를 줄이지 못한다.

이 수정 뒤에는 개별 HTML·JSONL 행·TXT·CSV 행·JSON을 zlib로 다시 압축했을 때
정답 4개가 1위가 되는 회귀도 발견됐다. 최종본은 의미 표현의 실제 길이를 다시 맞추고,
컨테이너 원문·긴 공백 제거본·추출 본문 세 종류의 재압축 순위를 모두 중간 범위로
감사한다. `audit.py`가 zlib 레벨 6·9에서 이 공격을 회귀 테스트로 포함한다.
독립 블라인드 검증은 zlib 1·6·9뿐 아니라 gzip·bzip2·lzma도 다시 실행했다. 공백을
제거한 MARKET 행의 bzip2 크기에서만 정답이 우연히 1위였지만, 다른 네 플랫폼에서는
같은 극단값이 재현되지 않아 전체 체인 지름길이 되지 않는다.

접미사를 제거한 뒤 whole-character n-gram, TF-IDF n-gram, 세 문장 최적 매칭으로
상위 1,000개 체인을 확장한 8개 문자유사도 변형에서도 실제 체인은 전부 순위 밖이었다.
따라서 표면 문자열만 일관되게 따라가는 경로는 의미 교집합을 대신하지 못한다.

TRAVEL의 단서 중 `승차권`은 교통 수단 표를 뜻한다. 이를 영화·공연 입장권까지 하나의
과도하게 넓은 `ticket` 범주로 합치면 세 후보가 생기지만, 원문은 이동 수단과 함께
명시해 의미적으로 구별된다. 풀이 사전도 이 구분을 유지해야 한다.

### AI와 결정론의 경계

AI는 서로 다른 표현의 개인적 경험을 연결한다. 최종 재료는 AI 출력이 아니라 각
파일의 정확한 ASCII `PROFILE-ID`다. 잘못된 ID 체인도 문법상 정상인 해시형 플래그를
만들기 때문에 플래그 형식이나 로컬 복호 성공을 게싱 오라클로 사용할 수 없다.
